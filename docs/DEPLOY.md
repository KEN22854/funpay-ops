# Работа 24/7 на сервере (VPS)

По умолчанию FunPay Ops работает только на вашем компьютере (`127.0.0.1`), без входа. Чтобы сканирование, уведомления и бэкапы шли круглосуточно, приложение можно запустить на VPS.

> ⚠️ Сервер в сети без защиты — это доступ к вашим финансовым данным. Приложение **откажется запускаться** в сети без `FPO_AUTH_TOKEN` длиной от 24 символов.

## Что нужно

- VPS с Linux (1 vCPU, 1 ГБ RAM достаточно), Docker и Docker Compose.
- Доменное имя с записью A на IP сервера — для HTTPS.
- Обратный прокси с TLS. Ниже пример с Caddy: он сам получает сертификат.

## Шаги

1. **Скопируйте проект** на сервер:

   ```bash
   git clone https://github.com/KEN22854/funpay-ops.git
   ```

   ```bash
   cd funpay-ops
   ```

2. **Создайте `.env`** (в git не попадает):

   ```bash
   cat > .env <<'EOF'
   FPO_AUTH_TOKEN=замените-на-длинный-случайный-ключ-от-32-символов
   FPO_PUBLIC_HOSTS=ops.example.com
   EOF
   ```

   Случайный ключ можно получить так:

   ```bash
   openssl rand -hex 32
   ```

3. **Создайте `docker-compose.yml`** рядом с проектом:

   ```yaml
   services:
     app:
       build: .
       env_file: .env
       environment:
         FPO_HOST: 0.0.0.0
         FPO_SECURE_COOKIE: '1'
       volumes:
         - ./data:/app/data        # база, бэкапы, токен Telegram
       restart: unless-stopped
     caddy:
       image: caddy:2
       ports: ['80:80', '443:443']
       command: caddy reverse-proxy --from ops.example.com --to app:5181
       volumes: ['caddy:/data']
       restart: unless-stopped
   volumes:
     caddy:
   ```

4. **Запустите:**

   ```bash
   docker compose up -d --build
   ```

5. Откройте `https://ops.example.com` и введите ключ доступа.

## Как это защищено

| Мера | Что делает |
|---|---|
| `FPO_AUTH_TOKEN` | Без него сервер в сети не стартует; вход выдаёт cookie `HttpOnly; SameSite=Strict; Secure`; список входов и отзыв — «Настройки → Сессии входа» |
| Ограничение попыток входа | 5 в минуту с одного адреса |
| `FPO_PUBLIC_HOSTS` | Только перечисленные имена хоста принимаются (защита от DNS rebinding) |
| `FPO_SESSION_TTL_DAYS` | Срок сессии входа, дней (по умолчанию 30). Сессии хранятся в базе и переживают перезапуск |
| `FPO_SESSION_IDLE_DAYS` | Сессия закрывается после стольких дней без активности (по умолчанию 7) |
| `FPO_BACKUP_KEY` | Пароль шифрования бэкапов (16+ символов): к каждой копии — файл `.enc`, AES-256-GCM |
| `FPO_BACKUP_EXTERNAL_DIR` | Папка для зашифрованных копий вне сервера (смонтированный облачный диск, отдельный том) |
| Проверка `Origin` + заголовок `X-FPO-Client` | Защита от CSRF |
| `Idempotency-Key` | Повтор финансовой операции не выполняется дважды |
| Ограничение частоты | Сканы, автопоиск, перепроверки, бэктест, бэкапы |
| TLS | Терминируется Caddy; сервер приложения наружу не открыт |

API также принимает `Authorization: Bearer <FPO_AUTH_TOKEN>` — для скриптов.

## Наблюдение и восстановление

- `GET /api/health` — состояние сервера: подходит для внешнего мониторинга, например Uptime Kuma.
- «Настройки → Автодиагностика» — целостность базы, источники, бэкапы, свежесть данных.
- Telegram-уведомления о сбоях источников и бэкапов.
- **Бэкапы** лежат в `data/backups`, по умолчанию раз в сутки, хранится 14 копий, каждая проходит тест восстановления.
- **Внешний бэкап.** Копируйте `data/backups` за пределы сервера. Пример для cron:

  ```bash
  rsync -a /path/funpay-ops/data/backups/ user@backup-host:funpay-ops/
  ```

- **Восстановление.** «Настройки → Резервные копии → восстановить». Перед восстановлением текущая база автоматически сохраняется в отдельную копию.
- **Обновление:**

  ```bash
  git pull && docker compose up -d --build
  ```

  Миграции применятся при запуске. Перед этим полезно выполнить `npm run db:check` на копии базы — см. [MIGRATIONS.md](MIGRATIONS.md).

## Правила площадки

Сервер читает только публичные страницы FunPay и источников с паузами между запросами и кэшем. Не ставьте автоскан чаще, чем нужно: частые запросы с одного IP могут привести к временной блокировке. Автоматические покупки и действия на FunPay от вашего имени приложение не выполняет — это осознанное ограничение (см. README, «Безопасное использование»).
