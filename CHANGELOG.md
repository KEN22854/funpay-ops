## [2.1.0] — 2026-11-12 · схема БД v3

Реализация обновлённого технического аудита (ноябрь 2026): доказательность рекомендаций.

### Добавлено
- **Единый финансовый движок** `shared/finance.mjs` для калькулятора, журнала, сканера, склада, paper trading и бэктеста. Тест паритета прогоняет 300 случайных сделок через все пути и сверяет с формулой из ТЗ.
- **Profit Verification.** Новые статусы:
  - «Кандидат» — проверки пройдены по котировкам;
  - «Исполнимо» — цена перепроверена мимо кэша, наличие подтверждено;
  - «подтверждено своей сделкой».

  Кнопки «Проверить сейчас» и «не вышло»; «купил» доступно только для исполнимых связок.
- **Качество данных источника** отдельно от транспорта:
  - полнота и правдоподобие котировок;
  - точность цены и остатка по попыткам закупки;
  - возвраты и споры по товару источника.
- **Строгое сопоставление:**
  - скины по умолчанию подтверждаются вручную, потому что float, паттерн и наклейки источники не передают;
  - диапазон float для лотов FunPay;
  - ограничения активации ключей («нужен VPN», «не активируется в РФ»);
  - невыбранные варианты из фильтров раздела FunPay отклоняют DLC и другие издания.
- **Demand Intelligence:**
  - вероятность продажи за 1/3/7/14 дней по своим продажам (Каплан–Мейер с остатками как цензурированными наблюдениями, 95 % интервал);
  - ценовые диапазоны и оптимальная цена при достаточной истории;
  - продажи по дням недели;
  - минимум наблюдений для сигналов рынка.
- **Capital & Risk:**
  - лимиты доли капитала на товар, источник и категорию;
  - резерв денег под плановые закупки;
  - старение запасов и замороженный капитал;
  - прогноз денежного потока на 7/14/30 дней;
  - потери на возвратах, обученные по своим сделкам со сглаживанием.
- **Paper trading** по стратегиям fast / balanced / max с закрытием по рыночной переоценке.
- **Бэктест** без заглядывания в будущее. Метрики: net profit, ROI, win rate, false positives, просадка, оборачиваемость, загрузка капитала, ошибка прогноза. У каждой рекомендации и прогона сохраняются версия движка и отпечаток параметров.
- **Страница «Качество и риск»:** метрики продукта из аудита (precision, false positive rate, Net P&L, ошибка прогноза прибыли и срока, sell-through, загрузка капитала, точность источников).
- **Частичное исполнение закупки:** получено меньше заказанного — разница возвращается в кассу.
- **Серверный режим для VPS:** `FPO_HOST` + обязательный `FPO_AUTH_TOKEN`, вход с cookie, ограничение частоты; Dockerfile, [docs/DEPLOY.md](docs/DEPLOY.md).
- **CI** (GitHub Actions: Node 22.13 / 22.x / 24.x: тесты, сборка, проверка миграций); `npm run db:check` — проверка миграций и восстановления на копии базы.
- **Тесты (147):** фикстуры адаптеров (пустой ответ, смена формата, 429, Cloudflare, сеть), SSRF, аварийное завершение процесса, конкурентные запросы, защита API, серверный режим.

### Изменено
- Ранжирование возможностей по умолчанию — по ожидаемой прибыли в день оборота, а не по проценту маржи.
- Неизвестное наличие у источника больше не допущение: связка остаётся «кандидатом» до подтверждения.
- Ключ идемпотентности записывается в одной транзакции с операцией.
- Ссылка на раздел FunPay принимается только с хоста `funpay.com`.
- Требование к Node.js: **22.13+** (раньше было указано 22.5: там `node:sqlite` требует флаг).

### Исправлено
- Калькулятор и сервер считали прибыль разным кодом.
- Без заданного капитала первая же сделка блокировалась как «100 % капитала».
- Одна-две своих продажи задавали срок продажи и завышали прибыль в день.
